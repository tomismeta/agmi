# agmi

**Agents Gonna Mine It.** A small Rust runtime for MinePOA participation.

## Product contract

- One Cargo package, one binary, one durable state authority per identity.
- Existing accounts and credentials remain local. Shared code does not mean shared identity, answers or state.
- Fresh accounts start paused. Existing agmi configuration and journals cross the atomic-capability boundary only through explicit stopped-writer migration; there is no arbitrary bot-state importer. Historical uncertainty remains recorded, never silently declared resolved. Explicit lane policy can authorize bounded active overlapping work without clearing uncertain operations; opt-in accepted-linked answer accounting does not bound accumulated eligible historical unknowns.
- Public source contains no operator identities, machine paths, credentials or private answer histories.
- No transfers, swaps or governance automation. Registration is explicit CLI administration, never a participation-loop or startup action.

## Boundaries

`config` owns validated operator policy. `protocol` owns MinePOA transport, payload decoding, immutable request context and scoped restrictions. `solver` owns typed native answer/judge execution and sourced completion facts, not lane eligibility. Lane controllers own their semantic matchers, scheduling and retained tasks through role-specific services; they cannot obtain the Store, Protocol client or sibling mutation ports. The private runtime host loads canonical operations from bindings and owns opaque ready effects. One coordinator arbitrates; Store alone validates guarded transitions and durable accounting. `health` is a local read-only projection and the CLI adapts these same capabilities. Adding a standard native lane extends the registry and explicit state provisioning, not existing lane controllers; this is not a plugin framework.

Models generate answers and judgments; they never own mining credentials, schedule work or submit transactions. Deterministic orchestration means the same recorded inputs produce the same state decisions, not that model output or the remote network is deterministic.

## Configuration

Answer, judge and mine each have `active`, `read_only` and `off` modes. Read-only permits observations/reconciliation but no new model calls or submissions. Off prevents new participation and ordinary capability polling; account-safety identity/job/receipt reads continue for possibly-sent work, including while paused. Stop the controller for no agmi network activity. Durable local diagnostics remain available.

Configuration schema 2 puts mode, deadlines, schedule and participation policy under each `capabilities.<lane>`. Answer and judge additionally own independent model, harness, reasoning, guidance and preparation settings. Mining is deterministic and has no model route. Identity policy and shutdown timing remain account/runtime concerns. There are no global solver, schedule or participation aliases.

Each lane owns its polling and retry cadence. Mining owns its interval or per-epoch mode. Protocol observations provide epoch, challenge words/constraints, assignments, eligibility and receipt state. Answer and mine observations are independently attributed; a late mine response cannot overwrite newer answer evidence. Identity-derived staggering needs no peer coordination.

Durable read keys distinguish identity, lane discovery, assignment and operation binding revision/phase. Local failure backoff belongs to that key, not a shared endpoint bucket. Reload may rebase only locally derived delay; absolute server and conservative legacy floors never move earlier or renew merely because configuration changed. A cooled or in-flight judge assignment does not prevent selecting another eligible assignment.

Transport captures response evidence with request identity and scope. Shared restrictions are ingested before stale local-result checks, while operation updates require the captured binding revision. Headers remain private until the response body completes or its deadline expires; there is no provisional header-only shared gate. A bare 429 without a valid minimum receives a locally sourced, versioned 30-second floor anchored to the original observation. Valid body/header minima suppress that fallback.

Ready effects use served-in-round fairness: among eligible unserved lanes, choose the earliest monotonic local observation-freshness deadline, then due time and stable lane ID. A round resets only when no eligible unserved lane remains; its flags commit atomically with dispatch intent. A continuously eligible lane is served within at most `2N−1` successful dispatch opportunities for `N` registered lanes. This is not a wall-clock SLA or a guarantee that upstream work will remain eligible. No lane reserves future capacity or bypasses shared identity, uncertainty, pause, server restrictions or the single effect gate. Admission records the offered lanes, eligibility/exclusions, round and selected deadline.

Reload validates the whole configuration before swapping it. Invalid edits retain the previous valid configuration and surface an event. Identity, chain, origin and credential reference are fixed for existing state; the canonical account binding also fixes its state directory across process lifetimes. Each model call records its chosen configuration; changed modes and pause state are rechecked before submission. No silent provider/model fallback.

API origins and route templates are full configuration, with bundled defaults in `defaults/network.toml`. Typed endpoints retain authentication, method, payload and effect semantics; paths cannot change those permissions. Templates are same-origin, chain-scoped paths with validated single-segment parameters. Configured routes remain trusted policy: a client cannot prove the remote semantics of an arbitrary path. Response-provided URLs are never followed.

The journal binds the effective routing profile before HTTP. Route changes require a stopped controller and no unresolved effects, confirmed operations still awaiting finality, or reusable model/prepared/retry work. Model-only rejected or superseded attempts remain reusable while their configured attempt budget permits another generation. Restart and recovery enforce the same boundary; restoring the recorded profile permits reconciliation without erasing uncertainty. Legacy journals with pending work accept only the frozen legacy routing fingerprint. Drained changes, including the first custom binding of a legacy journal, invalidate identity/eligibility observations and advance control generation so old manual grants cannot authorize new-profile work; server and conservative retry floors remain. Origin remains part of the immutable account binding; adding a trusted origin is explicit authority to deliver credentials there, not permission to rebind an existing journal.

`admin` owns schema discovery, revision-checked configuration patches and private guidance replacement. The CLI uses stdin for new configuration/guidance, validates the complete candidate and atomically replaces private files. A shared directory lock serializes cooperating administration and startup identity binding; external editors ignoring that lock are outside the guarantee. Saved source revision and controller-effective revision remain separate evidence. Reads may use a separate HTTP deadline; effectful mining GET requests always retain the write deadline.

Assignment exclusions are hot-reloaded admission policy, shared by every harness. They filter new judging selection and discard only proven-unsent captured work before backoff/activity gates. Model preparation and local abstention reload policy and compare the captured inventory generation under the existing admission gate; exclusion cannot silently consume an abstention attempt. They never erase or release possibly-sent operations.

Answer/judge each reference an explicit nonempty core guidance file for active model work and an optional user guidance file. Task/rubric prose is editable rather than embedded in solver policy; mechanical security and output constraints remain in Rust. Both bounded UTF-8 layers participate in configuration revisions and private attempt snapshots. Empty legacy core fields are omitted from serialization to preserve old captured request digests. Local safety controls and diagnostics load metadata without requiring either layer to be readable and do not claim a loaded revision for uninspected files.

## Durable effects

SQLite on local storage uses WAL and FULL synchronization. Private files and directories use restrictive permissions. Database transactions do not span HTTP or model waits. One owner commits binding-checked operation transitions. The independent account Binding retains database UUID/location, dispatch witness and immutable writer and account-admission inodes captured from held descriptors; required lane-gate inodes are journal authority. Ordinary acquisition opens existing anchored gates and revalidates after locking. Global control retains that accepted guard through commit and acknowledgment; lane-only control does not acquire the shared gate. Established missing/replaced locks fail closed, and a running Store never learns replacement anchors. First anchoring requires explicit stopped ownership and intact evidence, including stopping older controllers and native work; it cannot recreate lost established authority. No auxiliary raw database descriptor is used for inode checks. These fences detect database-only rollback across witnessed dispatch, not arbitrary history rollback, whole-host restoration or hostile same-user/root races. Journal format 4 excludes older writers that do not enforce lane controls; conversion is explicit.

Polling updates bounded per-scope observations and singleton controller evidence;
diagnostic events retain at most 2,000 rows. Operation and safety history remain
durable and grow with work, not every successful read. A covering
`(state,kind,updated_at)` index serves active-work selection and historical health
aggregates without scanning captured payload pages. Aggregate counts still scale
with history. Startup normalizes only identifiers whose stored case differs;
neither optimization prunes evidence or weakens WAL/FULL synchronization.

An intent is committed before model launch or HTTP mutation. Protocol submission preconditions are checked synchronously before dispatch intent; a local rejection cannot become an uncertain write. Accepted model output is retained rather than regenerated after transport failure. A crash after dispatch intent but before recording the response leaves an unknown operation. Unknown is not failed. Strict policy never automatically retries it; separately enabled uncertain-answer retry creates a linked attempt rather than changing the original outcome.

Preparation does not acquire the wallet-effect slot. The single transition owner runs bounded answer/judge tasks independently of observation; captured requests, policy, deadlines and attempt identities fence late results. A current answer can be prepared behind an unresolved effect under explicit configuration. Dispatch remains serialized locally, while explicitly authorized risk admission can overlap remote effects. Completed invalid drafts and uncertain inference have separate retry authority; the latter is opt-in and can duplicate remote model cost. Mining cadence governs new mining work, not reconciliation of an existing effect.

Each lane retains one discovery/freshness pipeline and two reconciliation requests; answer and judge each retain one model task. Identity and effect admission remain single shared slots. Transport tasks return results; only the collector updates journal state. Pending identity is not failure and cannot stall other lane observations. Positive identity evidence is bound to client/control generation and expires from transport completion. Shutdown aborts and joins retained reads. An effect holds the shared admission guard through response bookkeeping; preparation, abstention and native launch defer rather than reacquiring that guard, while results and reconciliation remain live.

Protocol transport owns the HTTP deadline; solver owns the fixed original model deadline and prelaunch-versus-started classification. Preflight and inference start synchronously under account and selected-lane gates, before scheduling their asynchronous collectors. Pending waiting consumes the original budget: pause, revalidation and database contention cannot renew it or rerun discovery. Store captures the pending deadline immutably, commits launch authorization once, and checks observation freshness after transaction acquisition; the host rechecks freshness, deadline and continuity immediately before spawn. An expired postcommit permit produces truthful not-started evidence, not a stuck pending slot or duplicate launch. The controller owns shutdown policy without competing equal-duration wrappers. `run --once` captures a finite entry plan: at most two entry-due recoveries per lane, one model task per model lane and one effect per lane, plus bounded discovery/freshness. It does not wait for future deadlines, consume newly created grants or replenish completed work.

Before dispatch, identity verification starts alongside eligibility refresh and is consumed only after freshness succeeds. This avoids repeating a slow inventory solely to start identity verification. Its completion-age, client and generation fences remain; urgent answer work may consume the single-use permit first.

Selected judging input remains in the current continuation while its bounded identity request completes, with urgent answer work still serviced. This preserves usable partial inventory when a later page imposes a retry floor; it does not bypass that floor or authorize dispatch without a fresh eligibility check.

Queued jobs, ledger inclusion and checkpoint claims are separate observations. A successful poll is interpreted through the original submission classifier. A bound `408 job_expired` is authoritative nonprocessing: clear the expired job binding, wait, recheck eligibility and make a fresh hosted submission using the captured content. Missing jobs, receipt 404s and unrelated nonce movement do not prove nonacceptance. Retry headers survive malformed response bodies. A timeout changes local waiting, not remote truth.
A bound done-job `stale_seed` with required nonce evidence becomes stale rather than a permanently attempted rejection. Fresh challenge/identity checks and the existing dispatched-answer/model budgets govern regeneration. Missing nonce evidence and direct ambiguous responses remain unknown; no generic HTTP status implies nonacceptance.

Hosted assignments supply their target `answer_epoch`; the inventory epoch is not the answer epoch. Those chain-scoped protocol observations bind the candidate and words used for judging. Missing target-epoch metadata requires selected-transaction hydration. Grading success returns the transaction identifier as `id`; it is journaled before a separate receipt lookup establishes inclusion. These are node-reported observations, not independently verified ledger proofs.

Assignment selection paginates within a fixed budget, canonicalizes IDs and orders by expiry/epoch. Freshness checks for an already prepared judgment stop when the selected assignment is found; unrelated later pages cannot delay that dispatch. Partial pages remain useful, but coverage never proves absence. Candidate-bound author history explicitly reports missing/supplied/truncated evidence; absent original words prevent a judgment. Numeric/range validation cannot prove semantic grading correctness.

Missing or empty original words prevent model preparation, so an unjudgeable earliest-expiring seat cannot monopolize selection. Answer and judge publish comparable sourced assessments with original observation time, finite validity, coverage and explicit unknown outcomes. Read-only judging may hydrate candidate evidence and assess it without creating operations, grants or model work. One stamped runtime snapshot is the current assessment authority; configuration, account generation, lane-control revision and runtime authority fence stale updates. Partial inventory never proves global absence. The retired selection cache is not recreated for fresh journals; historical migrated rows are not admission authority.

Only matching authoritative evidence resolves an uncertain operation. Strict policy blocks conflicting mutation; bounded `participation_first` permits selected capabilities after uncertainty grace, subject to unresolved-operation and per-epoch attempt caps. Explicit `participation_first` with `max_unresolved_operations = "unbounded"` instead admits distinct fresh work without a cumulative history ceiling or blanket account-wide uncertainty grace. `manual` retains its stopped-writer, epoch/lane/account-generation/lane-control-revision-bound, revocable one-dispatch grant. Server retry minima, live dispatch, identity, pause, freshness and same-work/epoch fences remain authoritative. Local serialization does not establish upstream serialization with delayed requests or server-side auto-mining.

Numeric quotas count only the selected lane's possible effects; another lane cannot borrow the allowance. Unbounded participation-first intentionally accepts potentially growing remote exposure, incomplete attribution and durable history. It never turns age, missing jobs or unrelated acceptance into terminal evidence. Its admission fast path checks relevant local authority, restrictions and specific work without reconstructing every historical unknown; unevaluated historical counts are not reported as zero exposure. Diagnostics can still report retained totals. There is no shared capacity pool or answer reservation.

Answer's `historical_unknown_answer_capacity` defaults to `bounded`, where default-zero `max_historical_unknown_answers` limits a separate historical capacity allowance. Participation-first alone may select `accepted_linked`, excluding eligible historical answers from finite answer capacity regardless of that numeric allowance. Eligibility requires a dispatched identifier-less unknown answer, a directly linked later retry in the same recorded epoch, and that retry's transaction ID with recorded `included_pending`, `confirmed` or `final` state. Originals remain unknown. No unrelated acceptance, transitive ancestry, judge/mine operation or elapsed age qualifies. Revoking a witness recharges finite answer capacity. This accounting authorizes risk, not settlement; it grants no same-epoch replay or strict/manual exemption.

Finite accepted-linked accounting uses revisioned original/witness link events (including revocation) and per-dispatch snapshots of witness revision and unresolved/eligible/exempt counts, retaining only active blocker IDs in the admission. Inspection reconstructs bounded witness examples at that revision, with counts and truncation explicit; status examples are bounded to 20. Original operations and accounting history are not pruned. Bounded-mode admissions retain finite copied witnesses; existing admissions remain readable.

Reconciliation has durable per-lane service pacing, bounded read slots and separate fair service for ordinary bound work and repeatedly missing jobs. Fresh discovery remains independent. A missing job can become a sparse background observation without changing its outcome or same-work fence; identifierless work has no invented lookup. Late evidence remains bound to its original operation. Indexed selections avoid sorting terminal history into the active queue. Finite `run --once` uses captured entry candidates, not newly arriving work. Retaining indefinitely many distinct unresolved identities still requires growing durable information.

Same-epoch uncertain-answer retry is separately opt-in, bounded and delayed even with a manual grant. Matching fingerprints reuse captured payloads; changed fingerprints require valid fresh preparation. Inclusion or provider-reported finality never permits duplicate answering merely because later confirmation is slow. Each lane has its own bounded rotating reconciliation cursor, so identifier-less old unknowns cannot consume another lane's recovery slots.

Selection does not consume the durable fairness cursor. A launch advances it only for a candidate eligible under its local read/operation clocks and genuine shared restrictions. A failed job cannot impose endpoint-global local backoff on healthy jobs.

Each lane may configure `queued_job_polling` separately from error retries and confirmed-finality reads. Capped intervals grow with retained queued-transition age, not process uptime; absent phase evidence uses the cap. Binding-local backoff and durable server/legacy minima dominate local policy. Reload retains already-scheduled deadlines. Already-due bound jobs participate in wake selection, so a bounded reconciliation batch does not strand remaining due jobs behind the normal poll sleep. This changes no classification or replay authority.

Per-epoch mining admission also counts adopted legacy dispatches without sequence evidence. Retained dispatch events distinguish previously sent discards from proven-unsent ones; discarded legacy work with pruned creation history counts conservatively. Scheduling and atomic dispatch share this query.

Outcome classification retains response source, safe diagnostics and bounded private candidate identifiers. Unvalidated candidates never become recovery bindings. A generic 429, 503, done/error body, duplicate-grade phrase or absent transaction ID is not sufficient proof of nonexecution. Recovery only follows identifiers already durably bound to the operation and validates returned bindings; present malformed identifiers fail closed. Identifier-less old unknowns may require upstream request-attribution support unavailable to this client. No model decides replay or ledger truth.

Global pause and lane pause are durable controls, not process stops. `lane pause|resume` requires the selected lane's opaque current control token; stale tokens conflict and a current-token no-op does not advance revision or event history. A successful pause acknowledges a local fence against new preflight, inference and effect admission, not remote cancellation or settlement. It waits only for its lane gate and bounded local lock acquisition, not a sibling's network/model work; stalled OS I/O is not a hard wall-clock guarantee. The selected effect retains account and lane gates through response bookkeeping. Already-durable unsettled dispatch and remote uncertainty remain visible in the acknowledgement.

Lane pause advances only its lane revision; account controls retain the shared generation. Resume removes only the selected override, changes no configured mode and grants no retry authority. Desired control, authoritative journal closure and last runtime observation are separate; stopped, stale or unverifiable observations never claim admission open. Pending unchanged model input may be revalidated by its owning lane under fresh authority while its original budget lasts; changed or expired input retires without rewriting producer provenance. Ordinary stop/activation preserves control intent and captured content, and shutdown collects already-completed results while retaining uncertainty for genuinely unfinished execution.

Health reads a consistent local SQLite snapshot without initializing state, contacting services or invoking a harness. Durable evidence retains current epoch, identity, captured work policy, transition/progress time and admission blocker separately from pruned events. Repeated observations do not reset blocker age or imply progress. Pending inference uses its captured original deadline, separately from launch authorization; a missing historical pending bound is unknown, not indefinitely healthy. Future-dated judge assessments invalidate aggregate clock evidence as well as the component. Desired/effective revisions remain distinct. Warnings and retained risk never alone change the successful exit status, while active admission blocks, stale or missing evidence, overdue work, exhausted finite capacity, strict-policy uncertainty gates and unhealthy disk floors do. A past unresolved operation never fails a lane solely because it exists, ages, or its background reconciliation returns 404/timeouts; this holds for finite headroom as well as explicitly unbounded participation.

The controller refreshes heartbeat before each bounded network wait; recovery reads do not impersonate controller liveness or reload model inputs. Captured timing takes precedence, effective timing is the fallback, and missing execution policy is reported as unavailable rather than inferred from desired settings. Journal build/lifecycle values are last reports, not live process identity; CLI diagnostics label process identity unverified. Installer status separately observes the actual systemd executable.
`reads` exposes `{reads, reads_truncated}`: at most 256 current resource records, prioritizing identity and lane discovery. Records distinguish HTTP versus usable success, failure category, local/server/effective deadlines and request state; remote resource identifiers are digest-only. Retired records remain durable, and presentation limits do not truncate pending-work scheduling. `status.work` derives per-lane next actions from captured effective revisions, preparation and canonical admission evidence without loading private guidance. None of these diagnostics contacts MinePOA.

Oldest unresolved-effect identity/time are reported as `oldest_unresolved_operation` and `oldest_unresolved_since`, with `oldest_unresolved_age_seconds` in health. They are historical risk evidence, not a causal blocker or continuous blockage duration. Configuration and installer errors retain bounded static reason codes and repair actions without raw parser, private value or subprocess text.

`status.work` and operation inventory expose state-scoped ages from durable operation timing, independent of bounded diagnostic-event retention; unavailable historical timing remains null. Mining never acquires a model-capture timestamp. Current reasons are not historical duration attribution. Canonical uncertainty accounting serves both dispatch and a read-transaction-local snapshot used by status; no persisted summary cache competes with operation/link/grant authority. Health separately projects operational conditions and unresolved-risk attention across controller, answer, judge and mine; operational clear is neither permission nor proof of remote availability, and a healthy result with warnings still reports attention required. Only a fresh complete judging inventory with no eligible work is idle and healthy; stale, partial or absent evidence stays unknown/degraded and never proves no available work. Current actions take precedence over background reconciliation, which stays visible without implying replay, clearing unknowns, or raising budgets. No diagnostic guarantees every retained outcome will resolve or proves independent finality.

Judging inventory carries bounded excluded-work identity/reason evidence, not just
aggregate counts. Current hydration failures are dependencies, not healthy idle.
Retained jobs are correlated to current assignments; missing or truncated
correlation remains unknown rather than making unrelated history current.

Health contract version 2 gives controller, answer, judge, mine and current API
resources the same `ok`, `degraded`, `blocked`, `unknown`, `disabled` vocabulary.
Effective lane modes, own quota and shared blockers determine capability health.
Stale, absent or truncated evidence remains explicit; a missing truncated binding
cannot authorize automatic recovery. Components are read-only projections, not
additional persisted state or probes. Operational health and retained risk differ.

Shared user-systemd units own process supervision and two-minute local health execution. CLI install/update/service commands use one canonical Rust installer for filesystem changes, hashing, unit rendering and control flow; only system integration uses subprocesses. No shell installer is retained. Incoming executables are privately copied and checked against an operator-trusted SHA256 before execution; the verified incoming release owns its installer/assets in a one-hop handoff. Fresh install enables but stays stopped; updates preserve runtime/timer running intent, enablement and pause generation unless explicitly stopped. Synced versioned sets, atomic publication and activation pointer, loaded/running identity checks, retained artifacts and journal/WAL headroom remain. Post-switch errors stop runtime/timer without automatically reverting the pointer or journal. Binary rollback requires compatible schema and never restores old state. Integrity labels are not signed provenance; dry-run is a nonexecuting plan.

Crossing supported journal formats 2/3 to current format 4 uses a verified, stopped, migration-only bootstrap; an old installed updater cannot cross it. Preview/apply tokens bind source state, candidate bytes, guidance and authority evidence. A FULL-synchronized journal seal owns conversion and restart recovery, not a stage file. A recognized historical seal without a target resumes only its exact original target-3 contract, unchanged token and evidence; a separate explicit preview converts that journal to current format. New approvals authenticate both writer and account-admission identities. Authentic earlier explicit-4 approvals retain their exact writer-only destination and require separate stopped admission-gate adoption before ordinary use; resume cannot enlarge their approval. Conversion preserves UUID and dispatch witness. Source-3 conversion preserves existing data/control intent; older conversion retains explicit pause/grant-revocation semantics. Completed conversion is acknowledged, never retroactively anchored. Pending migration fences ordinary mutations; status/private export remain available. Config-only migration creates neither journal nor account authority. No automatic participation, mixed-binary coexistence or downgrade follows.

Cargo ships an explicit source/asset allowlist with the thin native Python/Node adapters. `build.rs` derives manifest labels and embedded hashes only; it never installs, authenticates or provisions. An own-checkout Git identity takes precedence; extracted Cargo packages use parsed `.cargo_vcs_info.json` rather than an enclosing checkout. Missing/invalid identity remains unknown. Package VCS labels are metadata, not signed source proof. Native runtimes and harness authentication remain user-provisioned.

`lifecycle` owns explicit onboarding and local credential replacement. Init verifies an existing account through a read-only request, provisions private configuration/guidance and never registers or replaces journal history. Rotation requires paused/stopped initialized state and holds config-directory, credential-directory, admission and writer locks. Same-account verification precedes atomic credential replacement; config, guidance, unresolved work and durable journal remain untouched. Native harness authentication and provider key issuance/revocation stay outside agmi.

CLI action arguments bind the selected configuration to an absolute UTF-8 path, independent of an administering agent's later working directory. The CLI and installed service share `~/.config/agmi/config.toml`; custom configurations require separately supervised foreground instances. Health reports unobserved identity as not ready when unpaused active participation is configured, preserving null evidence rather than inventing a mismatch.

`registration` owns explicit `identity create`/`identity status`. Without confirmation, creation is a nonmutating plan. Confirmed work has finite PoW/hash/time budgets and exact operator-bound algorithm metadata. A private, durable intent precedes POST; a complete private response is captured before parsing its one-time credential. Re-entry after intent is local-only. Only a documented retained rejection permits an explicitly authorized new attempt after its retry floor. Successful capture publishes matching credentials/network metadata and exact verified-init arguments, without starting participation. A crash after remote creation but before durable response capture can permanently lose access; no idempotency or remote recovery guarantee is claimed.

`identity resume` plans recovery of retained registration evidence; `--confirm` authorizes only local create-only publication from a complete successful capture. It needs no original options or profile file and has no network or proof-search path. Incomplete capture remains unknown.

Derived credentials, identity metadata and network profiles use synced private temporary files and atomic no-replace rename, one file at a time. Local resume reuses exact matches and finishes missing publications from a complete successful capture without overwriting conflicts. Intent/capture files retain their conservative partial-write fences; this does not close the remote-creation lost-key window. Missing or mismatched proof algorithm approval reports `registration_pow_algorithm_unbound` before proof search, intent or POST. Invalid init configuration instead reports `initialization_invalid` with argument/profile repair actions before identity verification or onboarding writes.

Historical successful registration inspection does not require the current credential to remain byte-identical to the original capture. A differing credential remains unverified by that capture; local publication still refuses replacement. Credential rotation never rewrites the original registration outcome.

Hermes' expected authenticated API URL is `capabilities.answer.model.hermes_api_url` / `capabilities.judge.model.hermes_api_url`, defaulted from `defaults/model.toml`. Each must match its existing native authentication route; agmi never silently redirects native credentials or falls back to another provider/model. OpenClaw resolves its provider endpoint through its existing native configuration.

Agents may consume structured health, events and warnings and forward sanitized findings through existing native channels. Forwarding policy, credentials and delivery are agent-owned, outside agmi; the runtime contains no external notification transport or notification state. Local health stays read-only and grants no permission to replay uncertain model or protocol work. Agent forwarding does not establish host-down monitoring or human receipt.

## Harness adapters

Reuse native authenticated Hermes and OpenClaw interfaces, not copied OAuth credentials or alternate paid API routes. Hermes embeds its native isolated runtime. OpenClaw uses its public Gateway CLI transport through a small Node bridge and trusts the existing Gateway configuration/hooks. Requests select the model/reasoning, one-shot raw mode, no tools/bootstrap/delivery and a unique idempotency key; returned native run identity and execution evidence must match. Prompt data stays on stdin. Native admin authority is required for per-call model overrides; no shared configuration is mutated. Clearing environment variables alone is not filesystem isolation.

Local adapters are bounded and cancellable; a shared OpenClaw Gateway is not an owned descendant and may continue inference until its native deadline after the client exits. Lost launch acknowledgment remains unknown unless the native backend proves nonexecution. Finite `max_attempts_per_work` retains an actual attempt ceiling; explicit `"unbounded"` permits paced retries of conclusively finished unusable output while work remains eligible. `retry_uncertain` and `max_uncertain_replacements_per_work` separately bound automatic replacements for possibly-running same-work inference. Restart, age, config changes and manual abandonment do not refund possible execution or prove it stopped. Neither policy clears network uncertainty or measures dollars.

Producer/input provenance is separate from current dispatch policy. Admission-only configuration changes can reuse valid unsent output under fresh authorization without rewriting immutable producer facts. Changed model/guidance inputs, deliberately revoked authority and insufficient legacy provenance remain fences. Original per-attempt deadlines never renew during waiting or reload. Hermes uses native privileged policy messaging; the supported OpenClaw route retains its combined-message prompt-isolation limitation. Unsupported versions or routes fail without fallback.

Model retry maintenance uses bounded indexed recent and fair pages before cooldown filtering or deduplication, with durable service deadlines and restart-safe cursors. Permanently blocked keys do not force an all-history write transaction each controller turn. Accounting for a selected work key still inspects that key's retained attempts; no finite storage bound is claimed for indefinitely recurring work.

Model diagnostics cross the adapter boundary as typed, allowlisted categories. Native stderr, provider bodies, prompts and credential-bearing text are not diagnostic payloads. A diagnostic category never turns an unknown model attempt into proven nonexecution; failure presentation and retry authority remain separate.

The durable model-attempt record separates immutable producer/requested route, fresh launch authorization and write-once completion. Completion preserves safely parsed native-reported provider/model/effort/run facts even on invalid output or provenance mismatch; absence remains unknown. Recovery distinguishes permission from evidence of execution and never invents native reports. Status counts attempts and operation outcomes separately from assessments, correctness, payment and finality.

### Extension boundaries

Harness execution and network participation are separate extension dimensions, not current plugin APIs. The supported tasks and artifact validators remain MinePOA-specific. A future harness must preserve request binding, original deadlines, sourced execution evidence and conservative cancellation without receiving network credentials or journal-write authority. Extract shared execution machinery only when a concrete additional adapter demonstrates the common contract.

A different agent network requires its own task, acceptance, refusal and reconciliation semantics; changing endpoint URLs does not provide arbitrary-network support. Keep its account authority, credentials and uncertainty isolated. Separate runtime instances and state directories are the conservative starting point, not an implicit shared multi-network journal.

## Delivery plan

1. Implement strict configuration, protocol-derived capability semantics and public CLI discovery.
2. Implement native authenticated harness adapters with configurable model routes.
3. Implement durable answer/judge/mine execution, receipt reconciliation, hot reload, pause and local status.
4. Exercise the actual binary against local protocol fixtures: queued receipt, unknown write, restart, no-resend, read-only, mode reload, malformed config and pause.
5. Review security/lifecycle boundaries; document exact verification limits and unresolved upstream constraints.
6. After separate authorization, activate one host, prove actual authenticated participation, then expand the same release. GitHub publication and destructive legacy cleanup are separate approvals.

## Engineering principles

One core; explicit effects; typed protocol boundaries; stable JSON discovery; conservative mutation retries; private state; no secrets in output; small dependency surface; no unnecessary frameworks. Publish only what is exercised, distinguishing local tests from real harness and network proof.

Reference protocol: https://minepoa.com/go.md and https://minepoa.com/openapi.yaml. Prose, schemas and real responses may diverge; classify conservatively and document the evidence instead of inventing capabilities.
